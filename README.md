**Образ результата**

Помимо этого, в репозитории должен быть реализован главный скрипт run.sh, содержащий все необходимые команды для воспроизведения и проверки результатов.

**Генератор данных (2 балла)**
За вас реализован шаблонный скрипт по созданию CSV-файла с данными. Ваша задача — осознать его и подстроить под свою тематику: придумать названия колонок и добавить подходящие генераторы значений. Тематика любая — звери, люди, товары в магазине, что угодно.

После этого прогоните скрипт локально и убедитесь, что он работает и создаёт корректный CSV-файл.

Основная задача — упаковать этот скрипт в Docker-контейнер, который после запуска формирует файл data.csv в директории data/ локально на хосте. Подсказка: вам предстоит разобраться, что такое монтирование томов, вспомнить как правильно структурировать необходимые файлы, чтобы собрать контейнер

**Ключевой чекпоинт — через run.sh должны работать две команды:**

./run.sh build_generator   # собрать образ для контейнера генератора
./run.sh run_generator     # запустить контейнер, который сгенерирует data/data.csv локально
./run.sh create_local_data # в директории local_data создает data.csv (для локальной отладки)
Запрещено: вносить изменения в generate.py, кроме названий колонок и количества генерируемых строк, даже когда будете прогонять скрипт локально

*Подсказки:*

Основной файл — JavaScript-скрипт, который читает csv данные и формирует HTML-отчёт. Будет работать поверх образа node:20-alpine — в нём уже есть всё необходимое для запуска JS.
Локально воспроизводить не нужно и скорее всего не получится.
Скрипт использует внешнюю библиотеку, поэтому перед запуском необходимо установить зависимости. В мире Node.js это делается командой npm install — она читает package.json и скачивает всё нужное. Подумайте, на каком этапе это должно происходить.
Основная команда, которая должна выполняться при старте контейнера: node report.js.
Ключевой чекпоинт — через run.sh должны работать две команды:

./run.sh build_reporter    # собрать образ для контейнера аналитика
./run.sh run_reporter      # запустить контейнер, который сгенерирует html отчет локально в директории data
Чтобы проверить результат, загрузите report.html и откройте через любой онлайн-инструмент для просмотра HTML

Задание для терминаторов (2 балла)
Пробросьте HTML-отчёт на веб-сервер так, чтобы его можно было открыть в браузере вашего компьютера. Для этого потребуется разобраться с устройством портов и сетей в Docker.

Основная сложность в том, что большинство будет выполнять задание через GitHub Codespaces, а значит цепочка длиннее, чем кажется: веб-сервер работает внутри контейнера, контейнер — на хосте Codespaces, а хост Codespaces — не ваш компьютер. Нужно понять, как пробросить порт через все эти уровни.

*Подсказка: вам скорее всего понадобится запустить третий контейнер на образе, который встречался на семинаре.*
